MPLS VPN — Diseño & Implementación

Proyecto realizado en laboratorio (GNS3). Tecnologías: MPLS, LDP, MP-BGP (VPNv4), VRF, EIGRP. Objetivo: aislamiento por cliente y forwarding vía etiquetas.

1. Introducción

Este proyecto consistió en diseñar e implementar una topología MPLS VPN para ofrecer comunicaciones privadas y aisladas a múltiples clientes (CustomerA, CustomerB) sobre una infraestructura compartida. Se validó convergencia del backbone con EIGRP, distribución de rutas VPNv4 mediante MP-BGP, y forwarding mediante MPLS labels.

2. Marco teórico (resumen)

MPLS: reenvío rápido por etiquetas. VRF: tablas de ruteo independientes por cliente. MP-BGP: intercambio de rutas VPNv4 entre PEs. EIGRP: IGP del proveedor para convergencia interna.

Si necesitas que convierta esto a diapositivas o un documento técnico más formal, lo hago.

! Habilitar MPLS y LDP

3.2 PE routers — VRFs & MP-BGP (ejemplo) 

! PE example - VRFs and MP-BGP
mpls ip
mpls label protocol ldp

interface Loopback0
 ip address 10.255.255.11 255.255.255.255
 no shutdown
 mpls ldp router-id Loopback0

interface f0/0
 ip address 10.1.10.5 255.255.255.252
 no shutdown
 mpls ip

interface f0/1
 ip vrf forwarding customerA
 ip address 172.16.1.1 255.255.255.252
 no shutdown

ip vrf customerA
 rd 100:1
 route-target export 100:1
 route-target import 100:1

router bgp 400
 neighbor 10.255.255.1 remote-as 400
 neighbor 10.255.255.1 update-source Loopback0

 address-family vpnv4
  neighbor 10.255.255.1 activate
  neighbor 10.255.255.1 send-community both
  neighbor 10.255.255.1 next-hop-self
 exit-address-family
3.3 CE routers — BGP contra el PE (ejemplo CustomerA) 

! CE (CustomerA)
interface Loopback0
 ip address 192.168.2.1 255.255.255.0

interface f0/0
 ip address 172.16.1.2 255.255.255.252
 no shutdown

ip route 0.0.0.0 0.0.0.0 172.16.1.1

router bgp 65100
 network 192.168.2.0 mask 255.255.255.0
 neighbor 172.16.1.1 remote-as 400

4. Verificación y pruebas

Comandos esenciales y qué buscar:

  • show ip eigrp neighbors — adyacencias EIGRP.
  • show mpls forwarding-table — comprobación de etiquetas.
  • show ip bgp vpnv4 all — rutas VPNv4 en PE.
  • ping vrf customerA <ip> y traceroute vrf customerA <ip> — validar forwarding y ocultamiento de hops.
Comandos y salidas relevantes (ejemplos) 

! ej: verificar etiquetas
show mpls forwarding-table

! ej: verificar BGP vpnv4 en PE
show ip bgp vpnv4 all

6. Conclusiones y retos

Resumen práctico: el proyecto demostró cómo aislar tráfico por cliente con VRFs y MP-BGP, y cómo MPLS simplifica el forwarding mediante etiquetas. Retos comunes: RD/RT inconsistentes, redes no anunciadas en BGP/EIGRP y errores de máscara en interfaces.
